==== Information about the lambdas that are defined ====
get open games
    PATH: /open-games
    VERB: GET
    DESCRIPTION: gets the list of open games including settings
    INPUT:
    OUTPUT:
        list of games (json)

create open game
    PATH: /open-games
    VERB: POST
    DESCRIPTION: starts a new open-game. Also creates its match record and starts
        the game server for it (src/game_launcher.py), so the server is ready by
        the time the seats fill. The open_game_id is also the match_id.
    INPUT:
        session cookie (header) [must be logged in]
        game_name (body) [game server's name for the game, e.g. "ur"]
        settings  (body) [json, must include playerCount]
    OUTPUT:
        open_game_id (body)
        503 if the game server couldn't be started (no open game is created)

get match connection
    PATH: /open-games/{open_game_id}/match
    VERB: GET
    DESCRIPTION: what a player needs to connect to their open game's match. Only
        once every seat is taken and the game server is READY (or IN_PROGRESS)
        does it include the connect info; before that the lobby asks again.
        Seats go to the joined players in sorted order of user_id.
    INPUT:
        session cookie (header) [must be logged in, and have joined the game]
        open_game_id (path)
    OUTPUT:
        status (body) [WAITING_FOR_PLAYERS, or the match's status]
        when status is READY or IN_PROGRESS, also:
            match_id    (body) [same as open_game_id]
            path        (body) [where the game client connects: /m/{match_id}]
            player_id   (body) [your seat: "0", "1", ...]
            credentials (body) [your seat's secret, for boardgame.io]

==== Lambdas that are not part of the site API ====

route match connection
    NAME: mooseboardgames-router-dev (Lambda@Edge)
    CODE: lambdas/router/index.mjs   (deployed by infra/modules/game_host/router.tf)
    TRIGGER: CloudFront origin request on dev.mooseboardgames.com/m/*
    DESCRIPTION: sends a player's connection to the Fargate task hosting their match
        reads the match's status and origin_host; only READY and IN_PROGRESS are routed.
    INPUT:
        match_id (from the path /m/{match_id}/...)
    OUTPUT:
        request forwarded to the task, or 404 (no such match) / 503 (match not ready)
